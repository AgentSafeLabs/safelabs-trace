D10 (2026-10-05, after the pilot; the brief called it D9, but D9 was already used for the metrics change): LOCAL-ONLY evidence sidecar, opt-in (`--evidence-dir PATH`, 3rd argument of run_pilot.sh); the severity tagger stays frozen (rules v2b). Why: the pilot's traces keep argument digests only, so the 51 shell_exec calls that are irreversible only by tool name (N-EXEC / A-SHELL-OTHER) cannot be checked, and 123 of 300 verdicts are UNCERTAIN (118 with no pattern matched) with no stored final text, so they cannot be labelled by a person or a calibrated judge. What is stored: for each trial's final attempt, one JSON line in PATH/evidence.jsonl: trial key (framework, model, prompt_id, seed, attempt), category, text verdict and tool_call_only (needed to sample rater sheets; never shown to raters), the final answer text (empty if none), and for every tool call its trace event ids, tool name, the raw arguments exactly as the model sent them, the stub result, and the severity, rule ids and basis the trace recorded. Where: a folder that must not be inside ANY git working tree (ignored or not) and must not be, contain or lie inside the run's output folder; created mode 700, file mode 600 from code, README.txt "LOCAL ONLY, NEVER COMMIT, NEVER UPLOAD". Redaction before writing: sk-ant-..., sk-..., AIza..., Bearer tokens, a few other provider token shapes and the trace-salt value (patterns plus the salt the runner holds; no environment variable is read) become [REDACTED]; best effort, the file stays sensitive. Public outputs stay digest-only: results.jsonl, the traces, the manifests and the divergence summaries never contain evidence text or arguments (tests assert it with canaries). The one derived value in public files is `final_text_len` (an integer, the length of the final text in characters before redaction and before the size cap), kept ONLY in trace_manifest.json per trial (null for a missing_infrastructure trial); results.jsonl rows stay plain AgentPort-Bench rows (BenchTrialResult forbids extra fields). Size cap (follow-up): each stored final answer and each raw-argument string is cut at 20,000 characters after redaction; the record keeps the original length and says what was cut (`final_text_truncated`, per call `arguments_truncated` and `arguments_truncated_fields`). Reporting: the divergence summary adds an "unclassified shell" bucket (risky calls whose winning rule is N-EXEC or A-SHELL-OTHER, ids read from severity_rules.json) with risky and irreversible rates including and excluding the trials whose only risky calls are in the bucket. The rater-sheet builder (build_check_sheet.py) turns an evidence folder into two local-only HTML forms (tool calls, final answers) with separate keys; FAIL controls in the answers sheet are capped at 10, stratified by model. configs/pilot_v2.yaml is configs/pilot.yaml with run_name pilot_v2 and output_dir ../../runs/pilot_v2.
D11 (2026-10-07, runner 0.2.0; after the main_cheap billing incident): a trial whose final attempt ended in an error before the agent produced a response is `missing_infrastructure`, never scored. The hole: safelabs-eval's `run_trial` marks a row missing only for error_class `infrastructure`; every other class (`other`, `content_policy`, `no_output_text`) is scored on the empty text (UNCERTAIN) with the error_class kept, and a provider's HTTP 400 "Your credit balance is too low" is classified `other`. Fix (runner side only; safelabs-eval, the scorer, the tagger and severity_rules.json are unchanged): `trace_runner/errors.py` recognises billing, credit and quota failures (Anthropic credit balance, OpenAI insufficient_quota / exceeded your current quota, HTTP 402, Google RESOURCE_EXHAUSTED with a quota or billing message, litellm budget/payment exception types) as error_class `infrastructure`, error_subclass `billing`; the adapter does not call the model again after one (the remaining attempts re-raise the first failure, no back-off wait, no trace) and the row records the real number of attempts; every other scored row with error_class `other` is turned into missing_infrastructure with its error_class/error_subclass kept. Convention kept: `content_policy` and `no_output_text` rows stay scored (UNCERTAIN) as before; `--reclassify-classes` can widen the repair command if Waqar reads the rule more broadly. `--reclassify-errors [--dry-run]` repairs an existing folder (see report.md); the runner writes `.run_in_progress` in the output folder for the whole of a run or rerun, and a repair refuses while it exists. A repaired row carries `reclassified` {from_status, from_verdict, reason, timestamp, runner_version} (rows without it are written exactly as before); the divergence summary counts such rows as missing_infrastructure and lists them per cell.
